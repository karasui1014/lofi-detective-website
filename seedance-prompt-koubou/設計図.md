# シーダンス2.5 プロンプト工房 ─ 設計図

作成日: 2026-08-11 / 調査ベース: Seedance 2.5（ByteDance, 2026年7月31日リリース）

---

## 第1部｜調査結果：Seedance 2.5とは何が違うのか

### 1-1. モデルの基本スペック

| 項目 | Seedance 2.0 | **Seedance 2.5** |
|---|---|---|
| 1回の生成尺 | 数秒〜十数秒 | **30秒ワンパス**（ベータで最大180秒） |
| 参照素材の上限 | 画像9 / 動画3 / 音声3 | **画像30 / 動画10 / 音声10（合計50）** |
| プロンプト最大長 | 約3,500字 | **約15,000字**（プラットフォームによる） |
| 解像度 | HD中心 | **ネイティブ4K / 10bit出力** |
| 編集 | 再生成のみ | **タイムスタンプ編集・局所編集** |
| 音声 | 限定的 | 環境音・SE・セリフ・BGMを記法で指定 |

### 1-2. いちばん重要な変化

**「1枚の絵の説明」から「30秒のショット・ブリーフ（撮影指示書）」に変わった。**

2.0までは「美しい形容詞を並べる」で成立していたのが、2.5では
「誰が」「何秒に」「何をして」「どの素材の何を使い」「何を変えないか」
を書かないと破綻する。つまり **プロンプト＝映像制作の香盤表** になった。

これがそのままツールの存在価値になります。手書きだと確実に抜けが出る項目を、
UIで強制的に埋めさせて、正しい記法に組み立てて出力する。

### 1-3. 公式に近いプロンプト構造

```
被写体 ＋ 動作/出来事 ＋ シーンと環境(任意) ＋ ビジュアルスタイル(任意)
      ＋ カメラワーク(任意) ＋ 音声(任意)
```
必須は **被写体と出来事だけ**。他は全部オプション。

実務で使われている7ブロック版（PixVerse系ガイド）:

1. Subject（誰・何が映るか）
2. Action（尺の中で何が変化するか）
3. Setting（場所・時間・光）
4. Visual direction（質感・色・トーン）
5. Camera direction（ショットサイズ＋動き1つ）
6. Sound direction（環境音・SE・セリフ・音楽）
7. References（各素材の役割）

さらに実戦テンプレ（note/CreativeEdge系）は8セクション:
`[生成目標] [参照素材] [初期状態] [主要な出来事] [終了状態] [映像] [音声] [一貫性の維持]`

### 1-4. 記法（これはツールが自動付与すべき）

| 要素 | 記号 | 例 |
|---|---|---|
| 音楽 | `( )` | `(静かなピアノ)` |
| 効果音 | `< >` | `<遠くでベルが鳴る>` |
| セリフ | `{ }` | `{おはようございます}` |
| 字幕 | `【 】` | `【第1章：旅立ち】` |
| 参照素材 | `@Image 1` / `@Video 1` / `@Audio 1` | `@Image 1 は人物の顔と衣装のみを定義。背景は使わない` |
| 時間割 | `0-5s:` | `0-5s: 女性が左からフレームイン` |

セリフの語順ルール: **言語 → 地域変種 → 話し方 → 話者 → `{セリフ}`**
例: `Spoken language: Japanese, calm, the courier says: {もう大丈夫です}`

### 1-5. カメラ語彙（1ビートに1つだけ）

`dolly in / dolly out / truck left・right / pan / tilt / crane / arc(orbit) /
tracking / handheld / aerial / rack focus / locked-off`

**禁止: 1つのビートに動きを2つ以上重ねる**（最頻の失敗原因）

### 1-6. ライティング語彙

`golden hour / rim light / natural light / neon / backlit / overcast diffused /
practical light / moonlight / candlelight`

### 1-7. 失敗パターンと処方箋（＝ツールの検証ルールの原型）

| 症状 | 原因 | 対策 |
|---|---|---|
| 人物が入れ替わる | 画像と人物の1対1対応が未記述 | `@Image 1 は<店員>` と明示 |
| 物体が増殖する | 同一物の複数角度写真に「1個」宣言なし | 「3枚とも同じランプ1個。映像内は1個のみ」 |
| 動作が飛ぶ | 1ビートに状態変化を詰め込みすぎ | ビートを分割、静→動→静で設計 |
| 終点画像が歪む | 始点/終点画像のアスペクト比不一致 | 比率を揃える |
| 編集で全体が変わる | ソース動画を「唯一の編集マスター」と定義していない | `Edit @Video 1. Keep 〜. Change only 〜` |
| 感情が伝わらない | 抽象語のみ（「悲しそうに」） | 目・眉・呼吸・肩の具体的変化を書く |
| ブレ・手足の破綻 | 制約未記述 | `avoid jitter / bent limbs / identity drift / temporal flicker` |

### 1-8. 語数の目安

- 短尺・単発カット: **60〜100語**（2.0時代の黄金値、2.5でも1ビート分の目安として有効）
- 30秒フル構成: ビート数×80語 + 参照マニフェスト + 音声設計 ≒ 400〜900語

長ければ良いのではなく、**「ショットに実質的に影響する情報だけ」** が原則。

### 1-9. アクセス経路（2026年8月時点）

| 経路 | 日本から | 備考 |
|---|---|---|
| Dreamina (dreamina.capcut.com) | ◎ 使える | 国際版。最も現実的 |
| CapCut | ◎ | 編集まで1アカウントで完結 |
| Jimeng 即梦 | × | 中国の電話番号が必要 |
| Volcengine Ark API | △ | 公式は "coming soon" 表記が続いている |
| Runway / Higgsfield / PixVerse / OpenArt 等 | ○ | 各社が2.5を載せている。記法は共通、上限値が微妙に違う |

> ⚠️ **設計上の重要判断**
> API・料金・上限値は流動的。したがってこのツールは **APIを叩かない**。
> 「正しいプロンプト文字列を組み立ててコピーさせる」だけに徹する。
> こうすればどのプラットフォームが来ても壊れないし、APIキーも課金も不要。

## 第2部｜答え：使う人は何を用意すればいいのか

結論から言うと **「レベル制」**。何も要らないところから始められます。
ツールはこの3レベル（＋編集モード）をそのまま入口にします。

### レベル0 ─ 何も要らない（テキストのみ / T2V）

- **用意するもの: ゼロ。** 画像も台本もいりません。
- 「夕暮れの商店街を歩く配達員」だけで30秒が出ます。
- **限界**: 同じ人物を次の生成でもう一度出すことは**できない**（顔が変わる）。
- **向いている用途**: イメージ映像、Bロール、SNSの単発、MVの抽象カット。

### レベル1 ─ 画像だけ用意する（推奨・実用ゾーン）

- **用意するもの: 参照画像 4〜7枚**（50枚まで入るが、増やすほど破綻する）
- 内訳の型: `人物の顔 / 衣装 / ロケーション / 小道具・商品 / 色トーン見本`
- **各画像に「何を使い、何を使わないか」を書くのが必須。**
  例: `@Image 1 は人物の顔立ちと髪型のみを定義。背景と構図は使わない`
- **効果**: キャラ・商品・世界観が生成をまたいで固定される。シリーズ物が作れる。
- **向いている用途**: 商品PR、キャラもの、連作、ブランド映像。

### レベル2 ─ 世界観の台本まで用意する（フル演出）

- **用意するもの:**
  1. 参照素材フォルダ（人物/衣装/ロケ/小道具/トーンで分類）
  2. **30秒1シーンのコンテ**（起点→展開→着地）
  3. 音声設計（環境音・SE・セリフ・BGM、鳴るタイミング付き）
  4. キャラクター定義ブロック（3〜5個の視覚アンカーを毎回一字一句同じ文で使い回す）
- **「世界観の台本」は必須ではないが、30秒尺を活かすなら実質必須。**
  台本なしで30秒を投げると、モデルが勝手に間を埋めて散らかります。
- **向いている用途**: 広告、ショートドラマ、MV本編、企業案件。

### 編集モード ─ すでに動画がある場合

- **用意するもの: 直したい動画1本（20秒以下が安定）＋ 差し替え用画像**
- `Edit @Video 1. Keep the person and camera move. Change only the bottle to @Image 2.`
- 全部作り直さずに一部だけ直せる。**やり直しコストを激減させる最重要機能。**

### まとめ表

| | 画像素材 | 世界観の台本 | 音声設計 | 難易度 |
|---|---|---|---|---|
| **Lv0 おまかせ1カット** | 不要 | 不要 | 不要 | ★ |
| **Lv1 キャラ固定** | **必須 4〜7枚** | あると良い | 任意 | ★★ |
| **Lv2 フル演出** | 必須 | **必須** | 必須 | ★★★★ |
| **編集** | 動画1本＋差替画像 | 不要 | 任意 | ★★ |

## 第3部｜ツール設計図

### 3-0b. かんたんモードの書式（第4版）

かんたんモードの見出しを、専門用語ではなく**普段の言葉**にした。

| かんたん | こだわり（従来のまま） |
|---|---|
| `[参考]` | `[素材参照]` |
| `[内容]` | `[一文要約]` `[登場人物]` |
| `[展開]` | `[ショット／時系列]` `[映像]` |
| `[音]` | `[音声]` |
| `[固定]` | `[一貫性]` |

中身は同じものを出しているが、はじめて触る人が読んで意味の分かる見出しにしてある。
実装は `Builder.buildSimple()`。こだわりモードの `Builder.build()` は一切変えていない。

**その4つを埋めるための質問を、選ぶだけで答えられる形にした。**

1. **主役は何ですか？** — 人物 / 商品・モノ / 風景・場所 / キャラクター（`SUBJECT_KINDS`）
2. **場所** — チップ12種から選ぶか自由入力（`PLACE_CHIPS`）
3. **カメラの流れ** — 用途におまかせ / 静か→動く→静か / だんだん寄る /
   ゆっくり引く / ずっと固定 / 手持ちで追う（`FLOW_PATTERNS`）
   選ぶとビートに割り当てるカメラの並びが変わる。「おまかせ」は用途プリセットの流れを使う。
4. **固定** — 顔と髪型 / 衣装 / 商品の形と色 / 場所 / 全体の色味 / 人数・個数（`FIX_TARGETS`）
   選んだものが `[固定]` の指示文になり、それを守らせるための `avoid` も自動で足される
   （例: 顔と髪型 → `identity drift` `morphing faces`）。
   用途を選ぶと、その用途で崩れやすいものが初期値で入る。

> **なぜ選択式にしたか**: 「何を書けばいいか分からない」より前に「何を決めるべきか分からない」
> という段差がある。選択肢を並べると、決めるべき項目そのものが一覧になる。
> 自由入力は「主役の呼び名」「場所」「何が起きるか」の3つだけに絞ってある。

### 3-0a. かんたん / こだわり（第3版）

画面のいちばん上に**2つの入口**を置いた。作り込みたい人と、さっと出したい人で
必要なものがまるで違うため。

| | かんたん | こだわり |
|---|---|---|
| 入力 | 用途・画像・ざっくり台本の3つだけ | 全パネル（登場人物・ビート表・音声・境界フレーム…） |
| 画面 | 1枚のパネル | 9〜11枚のパネル |
| 尺・光・色・カメラ | 用途から自動 | 手で全部決める |
| 向き | 素材はあるが演出は任せたい | 1カットずつ作り込みたい |

**かんたんの中身**

1. **用途を選ぶ**（CM・広告 / MV / ショートドラマ / 商品紹介 / SNSショート / イメージ映像）
   → 尺・画面比・光・質感・色・ショットサイズ・カメラの流れ・avoid・一貫性ロックが一括で入る。
   カメラは用途ごとに「流れ」を配列で持ち、ビートに頭から順番に当てる
   （例: CM = 固定 → 寄り → 固定）。
2. **画像を置く**（複数まとめて可）。各画像は**役割を1つ選ぶだけ**で、
   `使う属性` と `使わない属性` が両方入る（`IMAGE_ROLES` の対応表）。
3. **ざっくり台本を1行ずつ書く**。行がそのままカットになる。

**台本の読み取り（`parseScript`）**

- `。` と改行で行に割る → 1行 = 1カット
- `「…」` `『…』` は台詞として抜き出し、その行のカットの開始+1秒に置く
- 台詞だけの行は直前のカットにくっつける
- 行が尺に対して多すぎるときは `groupInto()` でまとめる
  （上限 = `min(6, floor(尺/3))`。10秒に11行書いたら3カットに圧縮）
- 一文要約は「最初の行 〜 最後の行」

> ここでやっているのは**構造の読み取りであって、意味の理解ではない**。
> 日本語の文意からカメラや感情を推測することはしない（外すと直しづらいため）。
> 用途プリセットで演出を当て、文は素直にカットへ流す、という切り分けにしてある。

**2つのモードは同じ内部データを書く。** かんたんで作ってから「こだわり」に切り替えると、
ビート表も参照マニフェストもタグも全部埋まった状態で出てくる。行き止まりを作らない。

### 3-0. モード一覧（第2版）

| モード | 主タスク | 用意するもの |
|---|---|---|
| Lv0 おまかせ1カット | 新規生成 | ゼロ |
| Lv1 キャラ・商品を固定 | 新規生成 | 参照画像4〜7枚 |
| Lv2 30秒フル演出 | 新規生成 | 素材＋コンテ＋音声設計 |
| 編集 | 編集 | 直したい動画1本 |
| 延長 | 延長 | 伸ばしたい動画1本＋つなぎ目の状態 |
| 編集＋延長（2段階） | 編集 → 延長 | 直したい動画1本＋つなぎ目の状態 |

主タスクは1つに絞る。多素材参照・境界フレーム・キーフレーム・ストーリーボード・
3Dブロックアウト・感情・カメラ・音声は、どのモードにも重ねられる補助要素として扱う。

**編集と延長は1本のプロンプトに混ぜられない。** 両方必要なときは編集モードの
「このあと延長もする（2段階）」にチェックを入れると、実行順に2本出す。
1本目＝編集、2本目＝「プロンプト1で出来た動画」を元動画とする延長。
ビート表も2本になり、コピーボタンも別々。

### 3-1. コンセプト

> **「素材ゼロから始められて、レベルが上がっても同じ画面で作り続けられる、
> シーダンス2.5専用の香盤表エディタ」**

- 生成はしない。**プロンプト文字列を正しく組み立てて出力するだけ。**
- 最大の価値は **入力補助 ＋ 破綻チェッカー（バリデータ）**。
- カラスイさん流儀に合わせて **静的PWA・ローカル保存のみ・ビルド不要**。

### 3-2. 画面構成（1画面ウィザード + 右ペイン常時プレビュー）

```
┌─────────────────────────────────────────────────────────┐
│  シーダンス2.5 プロンプト工房          [履歴] [設定] [?]  │
├──────────────────────┬──────────────────────────────────┤
│ ① モード選択          │  【生成プロンプト】               │
│ ② 目的・尺・比率      │                                  │
│ ③ 被写体（キャラ定義）│   ここにリアルタイムで            │
│ ④ 参照マニフェスト    │   完成形が組み上がっていく        │
│ ⑤ ビート表（時間割）  │                                  │
│ ⑥ カメラ              │  ─────────────────────           │
│ ⑦ ライティング/画作り │  ⚠ 検証結果 3件                  │
│ ⑧ 音声設計            │   ・ビート2にカメラ動きが2つ      │
│ ⑨ 禁止・一貫性ロック  │   ・@Image 3 が本文で未参照       │
│                       │   ・「素敵な」を具体語に          │
│                       │  ─────────────────────           │
│                       │  [日本語][English][中文]         │
│                       │  [コピー] [保存] [.txt書出]      │
└──────────────────────┴──────────────────────────────────┘
```

モード選択で不要なステップは**自動で折りたたむ**（Lv0なら③④⑤⑧を畳んで3項目だけ）。

### 3-3. 各ステップの中身

#### ① モード選択
`Lv0 おまかせ1カット / Lv1 キャラ固定 / Lv2 フル演出 / 動画編集`
→ 選ぶと「今回あなたが用意するもの」チェックリストが出る（第2部の表をそのまま表示）

#### ② 目的・尺・比率
- 用途プリセット: 広告 / SNSショート / MV / ショートドラマ / 商品紹介 / Bロール
- 尺: 5s / 10s / 15s / 30s（→ ビート表の総尺に連動）
- 比率: 16:9 / 9:16 / 1:1 / 2.39:1
- 解像度メモ: 1080p / 4K

#### ③ 被写体（キャラクター定義ブロック）
- 人物カードを追加していく形式。1枚 = 1キャラ。
- 入力欄: `呼称ラベル（<配達員> など）` `年齢・体型` `髪` `顔の特徴` `衣装` `持ち物`
- **視覚アンカーを3〜5個に強制**（それ以上は入力欄が出ない）
- 保存すると **キャラライブラリ** に入り、次の作品で呼び出せる ← 連作の生命線
- 生成される文は毎回**一字一句同じ**にする（identity drift防止）

#### ④ 参照マニフェスト
素材の行を追加していくテーブル。ファイルは**アップロードしない**（ラベル管理のみ）。

| ラベル | 種別 | 役割（使う属性） | 使わない属性 | 紐づけ先 |
|---|---|---|---|---|
| @Image 1 | 画像 | 顔立ち・髪型 | 背景・構図・服 | `<配達員>` |
| @Image 2 | 画像 | ジャケットの色と質感 | 人物・ポーズ | `<配達員>` |
| @Video 1 | 動画 | 歩行のリズム | 見た目・場所 | `<配達員>` |
| @Audio 1 | 音声 | BGM | ─ | 全体 |

- 「同一物の複数角度」チェックボックス → ONで
  `@Image 3,4,5 はすべて同じランプ1個。映像内にランプは1個だけ` を自動生成
- 種別ごとに残数表示（画像 4/30・動画 1/10・音声 1/10）

#### ⑤ ビート表（時間割）※ここがツールの心臓
- 横棒スライダーで 30秒を分割。ドラッグで秒数配分。
- 各ビート: `時間` `出来事（動作の力学で書く）` `カメラ（1つだけ）` `音（この瞬間に鳴るもの）`
- **静 → 動 → 静** テンプレを初期値で入れておく（推奨構成）
- 隙間・重複が出たら即座に赤表示
- 「1ビートに詰めすぎ」検知: 動詞が3つ以上でwarning

#### ⑥ カメラ
- 8〜12種のカメラ語彙をボタンで選択（**ビートごとに単一選択、複数選ぶと弾く**）
- 開始ショットサイズ / 高さ・角度 / 終了ショットサイズ / ペース

#### ⑦ ライティング・画作り
- 光: golden hour / rim light / neon / backlit / overcast …（タグ選択）
- 質感: 35mm / cinematic / documentary / anime / clay render …
- 色: warm / cool / desaturated / high contrast …

#### ⑧ 音声設計
入力すると記法が**自動で付く**のが肝。ユーザーは記号を覚えなくていい。

- 環境音欄 → `<...>`
- SE欄（＋鳴る秒数）→ `<a bell rings> at 6s`
- BGM欄 → `(...)`
- セリフ欄（話者・言語・話し方・秒数）→ `Spoken language: Japanese, quietly, <配達員> at 26s says: {...}`
- 字幕欄 → `【...】`
- 「無音を指定」チェック → `No music, no narration, no random subtitles.`

#### ⑨ 禁止・一貫性ロック
- avoidタグ: `jitter / bent limbs / temporal flicker / identity drift / chaotic composition / extra fingers / warped text`
- 一貫性ロック: 「顔は最後まで同一」「小道具は1個のまま」「衣装は変えない」等をチェックで追加

### 3-3c. ストーリーボード／3Dブロックアウトの専用点検（第5版）

SKILL.md の点検項目のうち残っていた2つ——「ストーリーボードは15コマ以内・読み順・
各コマの役割」「粗い／精細な3Dブロックアウトで引き継ぐ情報と捨てる見た目を分ける」
——を、こだわりモードの参照マニフェストに実装した。

これまでは `REF_ROLE_PRESETS` の入力候補に文字列として名前が出ているだけで、
専用の入力欄も検証もなかった（「使う属性」に自由文で書くだけでは、コマ数を
数える・読み順の有無を見るといった機械的な点検ができない）。

**やったこと**

- 画像素材のカードに「特殊な参照」セレクトを追加（`SPECIALTY_KINDS`）。
  なし／ストーリーボード／3Dブロックアウト・粗／3Dブロックアウト・精。
  選ぶと「使う属性・使わない属性」もそれらしい初期値で埋まる
  （簡単モードの画像役割選択と同じ仕掛け）。
- **ストーリーボード**を選ぶと「読み順」と「各コマの役割（1行＝1コマ）」が出る。
  コマ数は専用の数値入力を持たず、**常にテキストの行数から数え直す**
  （数値とテキストがズレる事故を最初から起こさない設計）。
- **3Dブロックアウト**（粗・精）を選ぶと「引き継ぐ情報」「捨てる見た目」が出る。
  既定のプレースホルダーは「白模型の質感・色・素材」。
- 出力（`[素材参照]`）に、ストーリーボードなら読み順とコマ割りの列挙、
  ブロックアウトなら「引き継ぐ情報／実写の質感に置き換える」の1文を追加。
- 検証 V24（ストーリーボード）・V25（ブロックアウト）を追加。

**かんたんモードには置いていない。** ストーリーボード・3Dブロックアウトは
そもそも他のツールで作った素材を読み込む前提の上級者向け機能で、かんたん
モードの「3つ埋めるだけ」という設計目標と噛み合わない。かんたんモードで
作った参照はこだわりモードに切り替えても壊れず、そこから特殊な参照を
追加で足す、という導線にしてある。

### 3-3b. 第2版で入れた改良（外部スキル仕様書を反映）

Seedance 2.5用スキル仕様書（`SKILL.md`）と突き合わせて、次を改めた。

**直したこと**

1. **設定値を本文から追い出した。**
   長さ・比率・解像度・APIの境界フレーム指定は創作の指示ではないので、
   本文に混ぜると指示が薄まる。`推奨設定` として別ブロック・別コピーボタンに分離。
2. **節の順番を「素材参照 → 一文要約 → ショット/時系列 → 一貫性」に変更。**
   素材の役割を先に固定してから中身を書くほうが混線しにくい。
3. **`[一文要約]` を新設**（主体＋場所＋出来事＋ジャンル／スタイル＋カメラ）。
   ショットサイズ・カメラ高さ・テンポはここへ移し、`[映像]` は光と色に絞って重複を解消。

**足したこと**

4. **延長モード**（前方／後方）。編集と延長は別タスクなので混ぜない。
   両方必要なときは「先に編集 → その結果を延長元にする」と案内する。
4b. **編集 → 延長の2段階出力**。編集モードのチェックひとつで、実行順に2本のプロンプトを出す。
   2本目は「プロンプト1で編集して出来た動画」を唯一の延長元として書き、
   「プロンプト1で差し替えた要素は延長部分でも差し替え後の状態を保つ」を明記する。
   ビート表・秒数・コピーボタンが2本分に分かれる。

5. **最初・最後のフレーム**。2方式を明確に分けた。
   - 厳密指定（API `first_frame`/`last_frame`）＝比率が最初の画像にロックされる → `推奨設定` へ
   - 意味的参照（本文で「最初のフレームとして参照」）＝完全一致しない → 本文へ
   中間キーフレームは素材ごとの「キーフレーム秒」で指定。
6. **`[未使用素材]`**。素材に「今回は使わない」チェックを付けると明示的に列挙する。
   意図しない再参照を防ぐための安全策（公式の必須構文ではない）。
7. **記号記法のON/OFF**と**時刻指定のON/OFF**。
   `( ) < > { } 【 】` は読み違いを減らすための整理用記法であって公式必須構文ではないので、
   切れるようにした。短い単発カットでは時刻指定もむしろ邪魔になる。
8. **素材の役割プリセット**（datalist）。ストーリーボード、3Dブロックアウト（粗／精）を含む。

### 3-4. 出力テンプレート（Lv2フル構成の例）

```
[生成目標]
30秒・16:9・シネマティック。雨上がりの市場で、配達員が真鍮の筒を手渡すまで。

[参照素材]
@Image 1 は <配達員> の顔立ちと髪型のみを定義。背景・構図・衣装は使わない。
@Image 2 は <配達員> の緑のジャケットの色と質感のみを定義。人物とポーズは使わない。
@Image 3 と @Image 4 はどちらも同じ真鍮の筒1個。映像内に筒は1個だけ。
@Audio 1 は環境音のトーン参照。

[初期状態]
<配達員> はフレーム左外。市場の露店は開いており、路面は濡れて反射している。
カメラは地上1.6m、被写体の6m前方。

[主要な出来事]
0-5s: <配達員> が左からフレームイン、停車した路面電車の脇を歩く。カメラは同速で dolly out。
5-12s: 鐘の音に気づき歩みを緩め、狭い路地へ体を向ける。
12-22s: 露店の前で立ち止まり、左手をカウンターに置き、真鍮の筒を両肩から両手で持ち上げる。
22-30s: 筒を水平に回し、滑らせずにカウンターへ置く。カメラは arc right、ミディアムクローズで静止。

[終了状態]
筒はカウンター中央に静止。<配達員> は正面やや右を向き、肩の力が抜けている。

[映像]
ワイド→ミディアムクローズ。アイレベル。動きは1つ（dolly out → arc right）。
光: overcast diffused、路面のリムライト。35mm、シネマティック、やや低彩度。

[音声]
<ガラス屋根に当たる小雨> <遠くの路面電車のモーター> <濡れた路面の足音>
<真鍮の鐘が1回> at 6s
<筒が木のカウンターに触れる音> at 25s
Spoken language: Japanese, quietly, <配達員> at 26s says: {園丁さんへ}
音楽なし。ナレーションなし。不要な字幕を出さない。

[一貫性の維持]
<配達員> の顔・髪型・緑のジャケットは30秒間不変。真鍮の筒は常に1個。
avoid: jitter, bent limbs, temporal flicker, identity drift, warped text
```

Lv0の出力はこの1/5くらいの短文になります（被写体＋出来事＋光＋カメラ1つ）。

### 3-7. 技術構成

- **完全静的**: `index.html` / `app.js` / `builder.js` / `validator.js` / `data.js` / `style.css`
- ビルドツールなし、フレームワークなし、外部CDNなし（オフラインで動く）
- PWA（`manifest.webmanifest` + `sw.js`）でスマホからも使える
- 保存は **localStorage のみ**。サーバー送信なし。厳格CSP（`default-src 'self'`）。
- 出力: クリップボードコピー / `.txt` / `.json`（プロジェクト書き出し・読み込み）
- 公開は GitHub Web アップロード方式（既存プロジェクトと同じ手順）

> 実装時の変更点
> - 語彙辞書は `data/*.json` ではなく **`data.js`（プレーンなJS）** に集約。
>   `file://` で直接開いても動くようにするため（fetchだとCORSで落ちる）。編集しやすさは同じ。
> - Service Worker は **ネットワーク優先** にした。キャッシュ優先だと
>   ファイルを直したのに古い画面が出続けるため。オフライン時だけキャッシュへ落ちる。

### 3-9. 開発フェーズ

**Phase 1 ＋ 2（実装済み）**
Lv0/Lv1/Lv2/編集の4モードが全部動く状態まで一気に作った。
モード選択だけ作っても、参照マニフェストが無いとLv1が成立せず画面が破綻するため。

- モード選択・用途プリセット6種
- 目的/尺/画面比、登場人物（視覚アンカー）、参照マニフェスト
- 初期状態・ビート表・終了状態、映像（ショット/光/質感/色）
- 音声（記号自動付与）、禁止事項・一貫性ロック
- バリデータ V1〜V17 全部
- 日本語出力 ／ 日英ミックス出力
- localStorage保存・作品の保存/読込/削除・JSON書出/読込

**Phase 3（これから）**
- キャラライブラリ（作品をまたいだ人物の再利用）
- 作例ギャラリー（できあがったプロンプトの見本集）
- 英語のみ出力（本文の翻訳が必要なので、翻訳をどう用意するか要検討）
- アイコンPNG（現状は favicon.svg のみ。iOSのホーム画面用に180pxのPNGがあると尚可）

### 3-10. 設計上の割り切り（重要）

1. **APIは叩かない。** 上限値も料金も流動的なので、生成そのものはDreamina等に任せる。
   → 仕様変更で壊れない。無料で運用できる。
2. **素材ファイルは預からない。** ラベルと役割だけ管理する。
   → 容量問題・プライバシー問題が消える。
3. **上限値は `data.js` の `LIMITS` に外出し。** 30/10/10が変わっても1行直せば済む。
4. 語彙辞書も `data.js` に外出し。カラスイさんが後から語彙を足せる。
5. **英語のみ出力はやらない。** カメラ・光などの専門語は英語のほうが精度が上がるので
   「日英ミックス」を既定にしたが、本文まで英語にするには翻訳が必要で、
   ツール単体では正しく訳せない。中途半端な機械翻訳を出すより出さないほうが安全。
